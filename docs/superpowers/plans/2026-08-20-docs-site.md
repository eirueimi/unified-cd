# Documentation Site on GitHub Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `docs/` as a navigable MkDocs site on GitHub Pages, reorganized into an audience-oriented tree with the three largest files split into topic pages.

**Architecture:** MkDocs with the Material theme builds `docs/` into a static site. Navigation lives in `mkdocs.yml`, decoupled from file layout, so the tree can be restructured in stages. `strict: true` combined with `validation.anchors: warn` turns every broken internal link and every broken heading anchor into a build failure — that build is the test for every task in this plan. A GitHub Actions workflow builds on pull requests and deploys from `main`.

**Tech Stack:** MkDocs 1.6, Material for MkDocs 9.x, `mkdocs-redirects`, Python 3.12 (CI), GitHub Actions, GitHub Pages.

**Spec:** [`docs/superpowers/specs/2026-08-20-docs-site-design.md`](../specs/2026-08-20-docs-site-design.md)

## Global Constraints

- Python is a dependency of documentation work only. No Go build, `go test`, `make build`, or web-UI build path may come to depend on it.
- `mkdocs build --strict` must pass at the end of **every** task. A task is not complete with a red build.
- Prose is not rewritten. Tasks move, split, and relink existing text. Newly authored prose is limited to `docs/index.md` (Task 1), the generated-file notice on the field reference (Task 3), section overview pages that list their child pages (Tasks 4 and 6), and `docs/troubleshooting/index.md` (Task 5). Everything else is existing text under a new heading or a new path.
- Heading text is never edited during a split. Anchors are preserved verbatim so that inbound links need only their *path* changed, never their `#fragment`.
- `docs/superpowers/` is excluded from the site and is never moved.
- `CONTRIBUTING.md` stays at the repository root; GitHub's contribution UI looks for it there.
- Published site URL: `https://eirueimi.github.io/unified-cd/`
- Repository blob URL prefix for links that escape `docs/`: `https://github.com/eirueimi/unified-cd/blob/main/`
- Commit messages follow the repository's Conventional Commits style (`docs(site): ...`).

## Task 2: CI that builds on pull requests and deploys from main

**Files:**
- Create: `.github/workflows/docs.yml`

**Interfaces:**
- Consumes: `docs/requirements.txt` and `mkdocs.yml` from Task 1.
- Produces: a `Docs / build` check on every pull request touching documentation, and a deployment to GitHub Pages on every push to `main`.

- [ ] **Step 1: Write the workflow**

Create `.github/workflows/docs.yml`:

```yaml
name: Docs

# Path-filtered so ordinary Go changes never queue a docs build. CONTRIBUTING.md
# is included because the site pulls it in with pymdownx.snippets (Task 3).
on:
  push:
    branches: [main]
    paths:
      - 'docs/**'
      - 'mkdocs.yml'
      - 'CONTRIBUTING.md'
      - '.github/workflows/docs.yml'
  pull_request:
    paths:
      - 'docs/**'
      - 'mkdocs.yml'
      - 'CONTRIBUTING.md'
      - '.github/workflows/docs.yml'

permissions:
  contents: read

jobs:
  build:
    name: Build site
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'
          cache: pip
          cache-dependency-path: docs/requirements.txt
      - name: Install MkDocs
        run: python -m pip install -r docs/requirements.txt
      # --strict makes a broken internal link or anchor fail the PR.
      - name: Build
        run: python -m mkdocs build --strict
      - name: Upload the Pages artifact
        if: github.event_name == 'push'
        uses: actions/upload-pages-artifact@v3
        with:
          path: site

  deploy:
    name: Deploy to GitHub Pages
    if: github.event_name == 'push'
    needs: build
    runs-on: ubuntu-latest
    permissions:
      pages: write
      id-token: write
    # Never cancel an in-flight deployment: a cancelled deploy-pages run can
    # leave the Pages environment without a current deployment.
    concurrency:
      group: pages
      cancel-in-progress: false
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```
